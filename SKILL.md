# Интеграция с Aspro CRM

Скилл собран из реального проекта, прошедшего через все типовые ловушки
Aspro API. Содержит официальную OpenAPI-спеку (622 эндпоинта), поисковый
скрипт по ней и список граблей, на которые легко наступить.

## ⛔ Документация — сверяйся, НЕ выдумывай

В скилле лежит **полная официальная OpenAPI-спека Aspro API** —
`openapiru.json` (622 эндпоинта). Перед тем как обращаться к любому
эндпоинту, формировать тело запроса, перечислять поля или параметры —
**обязательно сверься со спекой**. Не сочиняй параметры, имена полей,
типы и формат ответа по памяти: у Aspro много неочевидностей, и догадка
почти наверняка будет неверной.

Файл большой (4 МБ) — целиком в контекст не грузи. Используй помощник,
он находит нужный эндпоинт и печатает параметры/тело/ответы с
развёрнутыми `$ref`:

```
python scripts/lookup_endpoint.py <часть-пути>
```

Примеры:
- `lookup_endpoint.py customer_payment` — все методы платежей
- `lookup_endpoint.py fin/customer_payment/create` — тело создания платежа
- `lookup_endpoint.py customfields/fields/list --list` — только список путей

Флаги: `--list` (только пути), `--full` (не обрезать описания).

> **Безопасность:** внутри `openapiru.json` в примере URL есть строка
> `api_key=...` — это иллюстративный ключ из официальной документации
> Aspro, НЕ рабочий ключ. Рабочий ключ держи в env-переменной
> (`ASPRO_API_KEY`). Не копировать ключ из спеки в код и не коммитить.

## Базовый URL и авторизация

```
https://<company>.aspro.cloud/api/v1/module/<endpoint>?api_key=<key>
```

- `<company>` — поддомен твоей компании в Aspro Cloud.
- `<key>` — API-ключ из настроек Aspro (Настройки → API).
- Ключ идёт **в query-параметрах**, не в заголовке Authorization.

## Красные флаги (реальные баги, на которых уже обжигались)

### 1. POST — это `x-www-form-urlencoded`, НЕ JSON

Тело запроса при `POST` сериализуется как form-urlencoded:
- `bool` → строка `"1"` / `"0"`
- `None` отбрасывается из тела
- Остальное приводится к `str`

Заголовок `Content-Type: application/json` **НЕ работает** — Aspro не
парсит JSON-тело. Это первая ловушка для всех, кто привык к REST.

### 2. `currency_id` — внутренние ID Aspro, НЕ ISO 4217

Aspro использует свои внутренние ID валют, не стандарт ISO 4217.
Например, в одной из инсталляций: BYN=10 (не 933).

**Правило:** при старте приложения загрузи маппинг валют один раз
(вызов `currency_mapping/list` или эквивалент в твоём тарифе) и
кэшируй в памяти. Пустой маппинг → создание платежей валится.

### 3. Кастомные поля шлются в ОБОИХ форматах одновременно

При создании/обновлении сущности кастомные поля шли сразу как
`cf_{id}` И `cf.{id}`:

```python
body['cf_123'] = value
body['cf.123'] = value  # обязательно ОБА, Aspro иногда игнорит один
```

Aspro в разных версиях/модулях игнорирует то один формат, то другой —
безопасно слать оба.

### 4. Список cf-полей — фильтр по модели только на клиенте

Чтобы получить список кастомных полей конкретной модели:

```
GET customfields/fields/list?customfields=1&model=<model_name>
```

**Фильтр `filter[model]=...` не работает корректно** — Aspro вернёт не
ту схему. Делай фильтрацию по модели на стороне клиента после получения
полного списка.

И **никогда не кэшируй «не нашёл» по cf-полю** — если поле добавят в
Aspro позже, ты его не подхватишь, пока не очистишь кэш.

### 5. Полю `total` в ответе НЕ доверять

В ответе пагинированного списка поле `total` Aspro присылает не всегда.
Если останавливаешься, когда `total` достигнут — на отсутствующем
`total` (=0) цикл оборвётся после первой страницы.

**Правило:** идёшь по страницам по 100 записей, пока ответ **короче**
лимита. См. `examples/python-client.md` → `aspro_get_all`.

### 6. Дедуп Aspro-сущностей — ТОЛЬКО по `aspro_id`

При синхронизации Aspro-сущностей в свою БД дедуп делай **только** по
`aspro_id` / `aspro_plan_money_id` (внешние идентификаторы Aspro), а
**не** по локальному PK. Если синк делает DELETE-then-INSERT, локальный
PK меняется каждый прогон → дедуп ломается → дубли алертов, дубли
проводок.

### 7. Вебхуки без подписи — авторизация на двух рубежах

У Aspro вебхуков нет HMAC-подписи. Защита делается так:

1. **Per-tenant токен в URL.** Генерируй случайный токен 32 байта,
   храни в БД компании, ставь в URL вебхука:
   `https://<твой-домен>/api/aspro/webhook/<token>`.
2. **Заголовок `X-Aspro-Secret`.** Aspro позволяет добавить custom
   headers. Добавь общий секрет (env `ASPRO_WEBHOOK_SECRET`), сверяй на
   входе. Без него → 403.

Не убирать токен из URL «потому что за Cloudflare» — без него эндпоинт
становится публичным.

Подробнее → `docs/webhook-setup.md`.

### 8. `aspro_id` под внешний источник — VARCHAR, не INTEGER

Когда хранишь `aspro_id` в своей БД, делай поле **VARCHAR/TEXT**, не
`INTEGER`. Внешние ID Aspro иногда приходят строками (особенно для
интеграций с банковскими источниками — история с одним банком давала
«invalid input for type integer»).

### 9. Rate limit и retry

Aspro лимитирует запросы. Жёсткой документации по числам нет, эмпирика:
- Минимум **1.5 сек между запросами** в одном процессе → не получаем 429.
- При нескольких воркерах (gunicorn workers > 1) общий поток быстрее →
  429 всё равно ловишь → retry спасает.

**Retry-политика:**
- Повторяй при `429`, `5xx`, `Timeout`, `ConnectionError`.
- НЕ повторяй при `4xx` кроме `429` — это твоя ошибка.
- Exponential backoff: база 2с, удваивай каждую попытку, cap 60с,
  максимум 4 попытки.
- Уважай заголовок `Retry-After`, если сервер прислал.

Реализация → `examples/python-client.md` и `examples/typescript-client.md`.

### 10. `customer_payment` + автопроводка в ДДС/P&L

При создании платежа `fin/customer_payment/create` с
`status=10` («Исполнено») + `status_pls=1` Aspro **обещает**
автоматически создать проводку в ДДС и P&L. На практике автогенерация
**ненадёжна** — иногда создаётся, иногда нет.

**Правило:** не полагайся на автогенерацию. Создавай проводку явно
вторым вызовом или проверяй наличие после создания.

## Типовые сценарии

### Принять платёж в Aspro (customer_payment)

1. Проверь маппинг валют (грабля #2).
2. Тело шли как form-urlencoded (грабля #1).
3. Кастомные поля — в двух форматах (грабля #3).
4. Если ставишь `status=10` + `status_pls=1` — проверь проводку
   отдельно (грабля #10).

### Принимать вебхуки

См. `docs/webhook-setup.md` — пошаговая настройка с двумя рубежами
авторизации.

### Синхронизировать список (проекты, сделки, акты, платежи)

1. Используй пагинацию по 100, идущую пока страница не короче лимита
   (грабля #5).
2. Дедуп по `aspro_id` (грабля #6).
3. Учитывай rate-limit (грабля #9) — в массовых операциях это даёт
   реальный выигрыш.

### Резолв кастомных полей

1. `customfields/fields/list?customfields=1&model=<...>` — получи
   полный список.
2. Фильтруй по модели на клиенте (грабля #4).
3. Не кэшируй «не нашёл» (грабля #4).
4. Найденное поле слать в обоих форматах cf_/cf. (грабля #3).
